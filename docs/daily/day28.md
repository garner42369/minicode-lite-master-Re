# Day 28：控制论基础——理解「受扰动的动态系统」，而不是堆控制器

## 今天要理解什么

前 27 天，我们把 Agent 当成一个「确定性的流程」：模型提议 → 工具执行 → 结果回填。Day 28
换一个视角：**Agent 是一个受扰动的动态系统**——Provider 抖动、大工具输出、测试失败，都会
让「上下文占用、成本速率、错误率」偏离目标，而且这些偏离会累积、振荡。

控制论提供的是一套**闭环框架**，回答「观测到什么、该做什么、做完效果如何」：

```text
观测（token/延迟/错误/进度/费用）
  → 控制器（PID / 规则 / 预测器）
  → 决策（压缩 / 减并发 / 收紧预算 / 换模型）
  → 执行
  → 记录结果作为下一次观测
```

## 五个概念（了解意义即可）

| 概念 | 一句话 | 对 minicode 的意义 |
| --- | --- | --- |
| 反馈 feedback | 运行后看误差，再纠正 | 上下文超了才压缩（我们现在就是这么做的） |
| 前馈 feedforward | 开始前按已知特征预设 | 知道是「跨模块重构」，一开始就多给预算 |
| 预测 predictive | 看趋势，在溢出前行动 | 上下文涨得快，提前压缩 |
| 观测 observer | 从噪声里平滑出真实状态 | token 估算有噪声，平滑后才知道真实压力 |
| 解耦 decoupling | 避免一个调节恶化另一个 | 压缩上下文时，别把记忆召回也弄坏 |

**这五个概念的价值在「思维」，不在「代码」**——理解「Agent 的某个指标会漂移、需要闭环纠
偏」，比实现一个卡尔曼滤波器重要得多。

## 诚实的判断：为什么「阈值可能够用」

minicode **已经有**「阈值压缩 + 熔断」的简单规则（Day 17/18）：

- `usage > 0.8 × window` → 压缩；
- 连续压缩无效 → 熔断，改用激进截断。

这套简单规则已经在干活了。PID 能不能做得更好？——这是 Day 29 消融要回答的，但**大概率结论
是「阈值够用，PID 只增加调参和解释成本」**。课件自己反复强调这一点（易错点原话：「控制器
数量不是质量。若一个阈值规则已足够稳定，PID 可能只增加调参和解释成本」）。

所以 Day 28 不做「把控制器全塞进 loop 跑效果」——那是用复杂度的幻觉替代「阈值已经够用」的
事实。Day 28 只做一件事：**把 PID 写对，作为理解控制论的落地**。

## PID：最小的「理解落地」

PID 公式就一句话：

```text
error = setpoint - measurement
output = Kp*error + Ki*∫error + Kd*d(error)/dt
```

写对它的关键不在公式，在两个工程点：

1. **输出限幅**：output 夹在 [min, max]，别让控制器输出离谱的值。
2. **anti-windup（条件积分）**：只在「输出未饱和」时才累积积分。否则执行器饱和期间，积分项
   持续累积，解除饱和后输出回不来（windup）。

这两点，写一遍就真正理解了「为什么积分要冻结」——这是「了解意义」的最小实现。

## 今天实际做了什么

| 文件 | 定位 |
| --- | --- |
| `pid_controller.py` | PID（限幅 + 条件积分 anti-windup + reset），**理解控制论核心的落地** |
| `context_cybernetics.py` | 阈值基线 vs PID 两策略 + 可重复模拟（**为 Day 29 消融准备的对比**） |
| `cost_control.py` | 成本闭环：控「消耗速度」不是「累计花费」（累计只能增加，不可控） |
| `feedforward_controller.py` | 前馈预配置（按意图预设 token_budget/max_turns/并发，按「万」量级） |
| `predictive_controller.py` | 趋势预测（指数平滑 + 短/长移动平均） |

前馈和预测是「了解意义」级别的轻量实现，不是完整复刻参考项目（参考项目的前馈每意图 15+ 字段、
预测是多指标 + 动作推荐，那些是「听起来高级、缺真实场景」的复杂度）。

## 能回答什么 / 不能回答什么

- ✅ Day 28 能回答：PID 实现正确（限幅、anti-windup、确定性）；阈值 vs PID 在模拟里的溢出/
  压缩对比（`test_baseline_vs_pid`）。
- ❌ Day 28 回答不了：**「自动调整有没有让真实任务更稳定、更省资源、不损害质量」**——这是
  Day 29 消融的事（阈值 vs PID 跑同一批真实任务，比成功率/工具错误率/步数/Token/费用）。
