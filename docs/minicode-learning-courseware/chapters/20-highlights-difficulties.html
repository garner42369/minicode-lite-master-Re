8.1 亮点、难点与解决方案

学习目标

  • 把 MiniCode 的技术点转成项目亮点。
  • 理解每个难点背后的工程问题。
  • 形成面试时可展开的讲法。

亮点一：自研 Agent Runtime

难点：不能只调用模型，因为 coding agent 需要多轮推理、工具执行、验证和失败恢复。

解决：用 agent_loop.py 和 turn_kernel.py 实现主循环和状态机，把任务拆成 explore、execute、verify 阶段，并记录 runtime event、stop reason、widening、guard 等过程指标。

面试讲法：我不是简单封装 LLM API，而是实现了一个本地 Agent Runtime，让模型通过受控工具完成代码分析、修改和验证。

亮点二：统一 Tool Calling 框架

难点：工具种类多，文件、命令、Git、测试、MCP 的风险和输出格式都不同。

解决：用 ToolDefinition、ToolRegistry、ToolContext、ToolResult 统一工具协议，通过 metadata 标注只读、破坏性、可并发和权限需求，并对大输出做智能截断。

面试讲法：我把工具从普通函数抽象成可注册、可校验、可审计、可限流的 Agent 动作。

亮点三：权限安全审查

难点：模型可能生成危险命令或错误文件修改，真实仓库不能无保护执行。

解决：路径访问限制在 workspace 内，危险命令进入审批，文件写入前生成 diff 并创建 checkpoint，支持 rewind 恢复。

面试讲法：模型只负责提出动作，真正落地前必须经过权限边界和变更审查。

亮点四：长上下文治理

难点：Agent 会不断读取文件、执行命令、收集测试结果，messages 很快超过模型窗口。

解决：用 token 估算、tool result budget、read dedup、micro compact、auto compact 和 reactive compact 分层治理，同时用 working memory 保护关键任务状态。

面试讲法：我把上下文当成有限资源，而不是无限往 prompt 里塞。

亮点五：分层记忆系统

难点：Agent 每次从零开始会重复犯错，旧记忆又可能污染上下文。

解决：把记忆分成 user/project/local 三层，结合 BM25、tag/category/domain、reranker、adaptive cooldown、reflection 和 feedback 实现按需召回和沉淀。

面试讲法：记忆系统不是聊天记录，而是从执行过程提炼可复用的项目经验和用户偏好。

亮点六：会话恢复和 Rewind

难点：长任务中断后，恢复不能只靠聊天历史，还要恢复文件状态和运行状态。

解决：session 保存 messages、transcript、permissions、readiness、checkpoints；文件修改前 checkpoint，支持 inspect、replay、rewind 和 reverse checkpoint。

面试讲法：我把一次 Agent 会话做成可检查、可回放、可撤销的运行现场。

亮点七：Harness 评估

难点：Agent 质量不能只看最后一句回答，过程质量同样重要。

解决：Runtime Eval 记录 model calls、tool events、runtime events、stop reason、verification guard；Cybernetic Ablation 比较 baseline 和控制器策略；Release Readiness 输出发布门禁报告。

面试讲法：我建立了 Agent 的可观测评估链路，用过程指标定位复杂任务中的稳定性问题。

本章小结

MiniCode 的核心亮点不是某一个库，而是 Agent 工程思维：运行时、工具、安全、上下文、记忆、恢复和评估共同构成一个可控系统。
