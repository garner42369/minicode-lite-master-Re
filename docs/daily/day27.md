## 今日任务

开始复现高级运行时，但**第一步不是做复杂 PID**，而是定义**可信观测**（任务复杂度、错误
率、延迟、上下文压力、成本、验证风险），再让「信号 → 规则/评分控制器 → 决策 → 执行 →
反馈」这条链转起来。

## 信号到决策闭环

```text
观测：复杂度、预算压力、延迟、近期失败、是否需工具/长上下文
  → 规则/评分控制器
  → 决策：模型、reasoning effort、验证范围、是否停滞
  → 执行
  → 记录结果作为下一次反馈
```

核心原则（课件易错点）：**「智能路由」最容易变成不可验证的启发式堆叠**——每个决策都要
能在固定信号下单测，并通过消融证明比固定策略更好，否则默认关闭。

## 评分公式详解（核心）

`choose_model` 给每个候选模型算一个分数，选分数最高的。总公式：

```text
score = 1 - |power - complexity|                    ── ① 能力匹配
        - budget_pressure × relative_cost × 0.5     ── ② 预算惩罚
        - latency_pressure × power × 0.2            ── ③ 延迟惩罚
```

下面逐项拆解：每个变量是什么、为什么用这个式子、系数的依据。

### ① 能力匹配：`1 - |power - complexity|`

- **变量**：`power ∈ [0,1]` 是模型能力（0 最弱、1 最强）；`complexity ∈ [0,1]` 是任务复杂度
  （0 最简单、1 最难）。
- **`|power - complexity|`** 是两者的**绝对距离**（L1 距离）。因为两个值都在 [0,1]，绝对值
  就是它们的「差距」，例如 power=0.9 配 complexity=0.85，距离 = 0.05；power=0.55 配
  complexity=0.85，距离 = 0.30。
- **`1 - 距离`** 把「距离」映射成「匹配度」：距离 0（完全匹配）→ 得分 1；距离 1（完全不
  匹配）→ 得分 0。
- **为什么用「距离」而不是「power 越高分越高」**：路由的目标不是「选最强的模型」，而是
  「选一个能力刚好够用的模型」。太强（power 1.0 处理 complexity 0.2 的任务）是「杀鸡用牛刀」
  ——浪费成本；太弱（power 0.3 处理 complexity 0.9）完不成。所以「匹配」才是目标，「距离」
  正好度量「匹配得怎么样」。这就是用绝对值差、而不是单调递增 power 的**根本依据**。

### ② 预算惩罚：`- budget_pressure × relative_cost × 0.5`

- **变量**：`budget_pressure ∈ [0,1]` 是预算压力（0 = 预算充裕，1 = 预算紧张）；
  `relative_cost` 是相对成本（1.0 = 最贵模型，flash 是 0.08）。
- **`budget_pressure × relative_cost`** = 「在当前预算压力下，这个模型有多贵」。压力 1.0 ×
  最贵 1.0 = 扣 0.5 分；压力 0.0（预算充裕）× 任何成本 = 扣 0 分（不惩罚）。
- **为什么乘 0.5**：让预算惩罚的最大影响力是能力匹配满分（1.0）的一半。也就是说，即使
  预算压力最大、模型最贵，也只扣 0.5 分，**不会完全压过「能力匹配」**——因为预算是「约束」
  不是「首要目标」，首要目标是「选对模型」。0.5 表达「预算的权重是能力匹配的一半」。

### ③ 延迟惩罚：`- latency_pressure × power × 0.2`

- **变量**：`latency_pressure ∈ [0,1]` 是延迟压力（0 = 不着急，1 = 要快）；`power` 是模型
  能力（这里假设「能力越强通常越慢」）。
- **`latency_pressure × power`** = 「在当前延迟压力下，强模型有多慢」。压力 1.0 × power 1.0
  = 扣 0.2 分。
- **为什么乘 0.2（比预算的 0.5 更低）**：延迟是「弱约束」——「强模型更慢」本身是弱假设
  （不一定成立，flash 和 pro 的延迟差异未必那么大），所以惩罚要比预算更轻，避免用一条
  不可靠的假设过度影响决策。

### 系数 0.5 / 0.2 的依据和局限

- **0.5 和 0.2 不是「算出来的最优值」，而是「设计时的相对权重」**，表达优先级：能力匹配
  （满分 1.0）> 预算（0.5）> 延迟（0.2）。
- 课件这个公式的价值在**结构**——三项各自含义清晰、可解释、可单测（给定 signal 必得确定
  结果）；**具体系数是「可调配置」**，不是「不可变事实」。
- 真正的「最优权重」要靠消融实验（Day 29）验证：固定任务集跑不同权重，比成功率和成本，
  明显更好的才改。这也呼应课件「每个决策都要能消融证明比固定策略更好，否则默认关闭」。

## 关键设计决策

1. **纯函数评分，不堆关键词**：课件线性评分每一项含义明确、可单测、确定性；参考项目关键词
   分类是魔法数字 + 漏词误判 + 集合重叠。
2. **复杂度是连续分数，基于意图映射**：意图已在 intent_parser 分类（SEARCH/DEBUG/CODE/
   REFACTOR），路由只做显式映射 + 长度/改动加成，不再重复「从文本猜复杂度」。
3. **Day 27 只做纯函数 + 单测，不接线**：课件明确「今天不要实现 PID 或自愈」，接线 + 消融
   是 Day 29 的事。
4. **fallback 不循环已由 model_switcher 保证**：本轮失败集合已记录，路由的 `failed` 集合
   排除失败模型，配合满足「Fallback 不循环」。
