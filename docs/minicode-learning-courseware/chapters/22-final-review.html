项目定位

MiniCode 是一个本地 AI Coding Agent Runtime。它不是 RAG 系统，也不是 LangChain Agent 示例，而是围绕真实代码仓库构建的模型推理、工具执行、安全审查、上下文治理、记忆沉淀、会话恢复和运行时评估系统。

一句话链路

用户提出开发任务后，MiniCode 通过 CLI/TUI 或 headless 入口装配配置、模型、工具、权限、prompt、记忆和会话状态，然后由 run_agent_turn 驱动模型和工具交替执行，最终完成代码读取、修改、验证和回复。

核心技术栈

  • Python 3.11+ 自研 Agent Runtime。
  • Anthropic Messages API。
  • OpenAI-compatible Chat Completions。
  • Tool Calling。
  • MCP stdio JSON-RPC。
  • 本地 Session Store。
  • Memory System。
  • Context Compaction。
  • Pytest / Benchmarks / CI / Docker。

最重要的六个亮点

  1. Agent 主循环工程化：阶段、策略、事件、停止原因可观测。
  2. Tool Calling 体系完整：工具注册、参数校验、异常兜底、输出截断。
  3. 权限安全可控：路径、命令、编辑、diff、checkpoint、rewind。
  4. 长上下文治理：预算、去重、压缩、超限恢复、工作记忆保护。
  5. 分层记忆沉淀：user/project/local、检索、注入、反思、反馈。
  6. Harness 评估：过程指标、策略对比、release readiness。

最核心的难点

MiniCode 的难点不是调用模型，而是让模型能在本地代码仓库里“真的干活”：

  • 干活要有工具。
  • 工具要有权限。
  • 长任务要有上下文治理。
  • 中断要能恢复。
  • 经验要能沉淀。
  • 失败要能观察和评估。

推荐面试表达

可以这样讲：

这个项目我更关注的是 Agent 工程化，而不是简单接一个模型 API。我把一次编程任务抽象成可观测的 Agent Turn，模型通过 Tool Registry 调用文件、命令、Git、测试等工具；工具执行前有权限审查和 diff checkpoint，执行过程中有上下文压缩和记忆注入，执行后会保存 session 并通过 runtime eval 观察完成状态、停止原因和工具轨迹。

本章小结

如果只记一句话：MiniCode 的价值在于把 AI Coding Agent 从“会聊天的模型”变成“能在真实仓库里安全执行、持续记忆、可恢复、可评估的本地运行时系统”。
